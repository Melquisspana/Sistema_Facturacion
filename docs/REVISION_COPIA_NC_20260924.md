# Copia verificable de formatos de NC — revisión en desarrollo (24/09/2026)

Claude Opus 5.5 implementó el archivado del Excel de un lote de NC en desarrollo. Agregó una migración aditiva: `database/migrations/2026_09_24_120000_add_copia_archivada_a_nc_exportaciones.php` incorpora hash SHA-256, ruta, procedencia y fecha de archivado, todos nullable. La primera descarga de un lote nuevo genera el Excel, archiva/verifica sus bytes y prepara esos mismos bytes para descargar. Las siguientes leen y verifican la copia sin volver a usar el exportador o el perfil actual. Copia faltante, corrupta, ilegible o registro parcial bloquean la descarga y no incrementan el contador. El nombre y el tipo MIME de Excel se conservan.

Los lotes descargados antes de existir esta copia no tienen bytes originales demostrables en la base. Al descargarlos de nuevo se crea una **reconstrucción histórica**, marcada persistentemente como tal en la ficha y el historial. Esa reconstrucción se archiva y sus siguientes descargas sí serán idénticas byte a byte. No se presenta como prueba de lo que recibió Calleja en el pasado. Descargar tampoco prueba que el navegador completó la transferencia ni que Calleja lo recibió; la descarga solo se registra después de preparar una respuesta con archivo válido.

Codex revisó migración, servicio, modelo, interfaz y pruebas. Detectó y devolvió a Claude un intento de la prueba de modificar `total_pagar` de una NC aceptada; el observer lo prohibió correctamente. La prueba ahora cambia solo el perfil y exige que la segunda descarga no invoque el exportador. Pint `--test` pasó. En la primera corrida amplia, **47 pruebas/284 aserciones pasaron y una falló** por aquel dato de prueba; tras corregirlo, la prueba afectada pasó (**1/16**) y los dos casos nuevos de procedencia incompleta pasaron (**2/20**). Las demás rutas de la corrida amplia no se volvieron a ejecutar porque no cambiaron después. La base de pruebas aplica la migración de forma aislada.

**Actualización 24/09:** por autorización expresa del usuario, Codex aplicó únicamente esta migración en la base de desarrollo local, tras verificar `APP_ENV=local` y conexión MySQL a `127.0.0.1`. `migrate:status` confirma `[84] Ran`; producción no se tocó. La función ya se puede recorrer en la aplicación local. No fue necesario aplicar ninguna otra migración.

Si el storage archiva los bytes y luego falla el guardado en DB, puede quedar una copia huérfana dirigida por hash. El contador actual no registra cada persona/instante por descarga, solo cantidad y primera fecha; el historial detallado de descargas que pidió el usuario sigue pendiente. Un archivo inválido aparece hoy como error HTTP 500, no como aviso accionable dentro de la interfaz. El exportador de NC aún deja un temporal vacío por usar `tempnam()` más `.xlsx`; también queda pendiente. No se cambió el formato aceptado, sus importes ni ningún DTE emitido.
